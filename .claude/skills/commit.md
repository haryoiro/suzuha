# Git コミット規約 — suzuha

## ルール

1. **日本語で書く**
2. **`git add .` は使わない** — 必ずファイルを個別に指定
3. **1コミット = 1論理単位** — 「〜と〜」で説明が必要なら分割
4. **依存される側から先にコミット**
5. **リファクタ/機能追加/テストは分ける**
6. **スコープ外の変更は確認する** — 無関係なファイルはユーザーに確認
7. **複数スコープの変更は避ける** — 分けられるのなら分けよう！

## 手順

1. `.gitmessage` を参照してフォーマットを確認
2. 変更ファイルを確認 `git status`
3. 差分を確認 `git diff <file>`
4. ステージング `git add <file>` (ルールに従い個別指定)
5. コミット作成

## コミットメッセージフォーマット

```
<emoji> タイトル

詳細説明
- 変更点1
- 変更点2
```

### emoji 一覧

| emoji | 用途                 |
| ----- | -------------------- |
| ✨    | 新機能               |
| 🐛    | バグ修正             |
| ♻️     | リファクタリング     |
| 📝    | ドキュメント         |
| ✅    | テスト               |
| 🔧    | 設定・ツール変更     |
| ⬆️     | 依存関係更新         |
| 🔥    | コード/ファイル削除  |
| 🚀    | パフォーマンス改善   |
| 🏗️    | アーキテクチャ変更   |

## アンチパターン

| NG                     | 理由                         |
| ---------------------- | ---------------------------- |
| `git add .`            | 意図しないファイルが含まれる |
| `fix` だけのメッセージ | 何を直したかわからない       |
| `WIP`                  | 不完全な作業                 |
| 1つの巨大コミット      | レビュー/リバートが困難      |
